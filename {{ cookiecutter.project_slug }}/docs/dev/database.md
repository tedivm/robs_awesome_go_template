# Database — bun ORM

{{ cookiecutter.project_name }} uses [bun](https://github.com/uptrace/bun) as its ORM. bun is a SQL-first ORM — it embraces SQL rather than hiding it. Queries are type-safe, explicit, and readable.

## Base Model

All domain models embed `BaseModel` from `internal/model/base.go`. It provides common fields:

```go
type BaseModel struct {
    bun.BaseModel `bun:"table:base,alias:b"`

    ID        uuid.UUID      `bun:"type:uuid,pk" json:"id"`
    CreatedAt time.Time      `bun:"type:timestamptz,notnull,default:current_timestamp" json:"created_at"`
    UpdatedAt time.Time      `bun:"type:timestamptz,notnull,default:current_timestamp" json:"updated_at"`
    DeletedAt *time.Time     `bun:"type:timestamptz,soft_delete" json:"-"`
}
```

| Field | Purpose |
|-------|---------|
| `ID` | UUID primary key, generated by `BeforeInsert` hook |
| `CreatedAt` | Timestamp set on creation |
| `UpdatedAt` | Timestamp updated on every modification |
| `DeletedAt` | Soft delete — non-nil means the record is "deleted" |

### Hooks

`BaseModel` implements the `BeforeInsert` hook to auto-generate UUIDs:

```go
func (b *BaseModel) BeforeInsert(ctx context.Context) error {
    if b.ID == uuid.Nil {
        b.ID = uuid.New()
    }
    return nil
}
```

Available bun hooks:

| Hook | When |
|------|------|
| `BeforeInsert` | Before INSERT |
| `AfterInsert` | After INSERT |
| `BeforeUpdate` | Before UPDATE |
| `AfterUpdate` | After UPDATE |
| `BeforeDelete` | Before DELETE |
| `AfterDelete` | After DELETE |
| `BeforeScan` | Before scanning rows to struct |
| `AfterScan` | After scanning rows to struct |

## Embedding

Embed `BaseModel` in every domain model:

```go
type Item struct {
    BaseModel `bun:"table:items,alias:i"`

    Name        string    `bun:"type:varchar(255),notnull" json:"name"`
    Description string    `bun:"type:text" json:"description"`
    CreatedBy   uuid.UUID `bun:"type:uuid" json:"created_by"`
}
```

The `bun:"table:items"` tag sets the table name. The `alias` tag sets the SQL table alias for joins.

## Tags

bun uses struct tags to define column types, constraints, and behavior:

| Tag | Description | Example |
|-----|-------------|---------|
| `type` | SQL column type | `type:varchar(255)` |
| `pk` | Primary key | `pk` |
| `auto` | Auto-generate value | Not used — UUID generated by `BeforeInsert` hook |
| `notnull` | NOT NULL constraint | `notnull` |
| `default` | Default value | `default:current_timestamp` |
| `unique` | UNIQUE constraint | `unique` |
| `soft_delete` | Soft delete column | `soft_delete` |
| `scan` | Custom scanner | `scan` |
| `-"` | Ignore field | `-` |

Combine multiple tags with commas: `bun:"type:uuid,pk"`.

## Associations

bun supports relational associations through struct fields:

### Belongs To

```go
type Item struct {
    BaseModel `bun:"table:items"`
    CategoryID uuid.UUID `bun:"type:uuid"`
    Category   *Category `bun:"rel:belongs-to,join:category_id=category.id"`
}
```

### Has Many

```go
type Category struct {
    BaseModel `bun:"table:categories"`
    Items     []Item `bun:"rel:has-many,join:category.id=category_id"`
}
```

### Many to Many

```go
type Post struct {
    BaseModel `bun:"table:posts"`
    Tags      []Tag `bun:"m2m:post_tags"`
}

type Tag struct {
    BaseModel `bun:"table:tags"`
    Posts     []Post `bun:"m2m:post_tags"`
}
```

The `m2m` tag references a join table. bun creates the join table automatically with `CreateTable`.

## Query Building

bun provides a fluent API for building type-safe queries:

### Select

```go
var items []model.Item
err := db.NewSelect().Model(&items).Where("name LIKE ?", "%search%").OrderDesc("created_at").Limit(20).Scan(ctx)
```

### Insert

```go
item := model.Item{Name: "Test", Description: "Description"}
_, err := db.NewInsert().Model(&item).Exec(ctx)
// item.ID is populated after insert
```

### Update

```go
_, err := db.NewUpdate().Model(&item).Where("id = ?", item.ID).Exec(ctx)
```

### Delete

```go
_, err := db.NewDelete().Model(&item).Where("id = ?", item.ID).Exec(ctx)
```

### Join

```go
var items []model.Item
err := db.NewSelect().
    Model(&items).
    Join("JOIN categories c ON c.id = items.category_id").
    Where("c.name = ?", "Electronics").
    Scan(ctx)
```

### Aggregate

```go
var count int64
err := db.NewSelect().Model((*model.Item)(nil)).Count(ctx, &count)
```

## Cross-Database Support

The template supports two database backends:

| Database | Use Case | Driver |
|----------|----------|--------|
| SQLite | Local development, testing | `modernc.org/sqlite` |
| PostgreSQL | Production | `github.com/uptrace/bun/driver/pgdriver` |

The database is selected via the `APP_DATABASE_DRIVER` environment variable or `configs/config.yaml`.

### SQLite for Development

```yaml
database:
  driver: sqlite
  dsn: app.db
```

SQLite requires no external service. It stores data in a file and works out of the box for local development.

### PostgreSQL for Production

```yaml
database:
  driver: postgres
  dsn: host=localhost user=postgres password=postgres dbname=app port=5432 sslmode=disable
```

PostgreSQL is the production database. Use Docker Compose to run it locally: `just docker-up`.

## Connection Pool Configuration

Connection pool settings are configurable via `configs/config.yaml` or environment variables:

| Setting | Default | Description |
|---------|---------|-------------|
| `max_open_conns` | 25 | Maximum simultaneous connections |
| `max_idle_conns` | 5 | Maximum idle connections kept in pool |
| `conn_max_lifetime` | 3600 | Maximum connection lifetime in seconds |

Tune these values based on your workload:

- **Read-heavy API:** Increase `max_open_conns` to handle concurrent requests.
- **Write-heavy workload:** Keep `max_open_conns` moderate to avoid overwhelming the database.
- **Containerized deployment:** Set `conn_max_lifetime` shorter than your orchestrator's pod rotation interval.

## Model Registration

bun needs to know about your models for schema operations. Register them in the application startup:

```go
// Register all models with bun's schema
db.RegisterModel((*model.Item)(nil))
db.RegisterModel((*model.Category)(nil))
```

This enables `CreateTable` operations and ensures bun can generate correct SQL for your models.
